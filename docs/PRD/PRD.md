## 2. 输入、过程和产物

本轮输入：用户提供的 GitHub 仓库。过程：检查源码与环境、运行离线入口和可执行工具、检查阶段目录和管家。产物：本地源码基线、可复现的运行方法、核验结果、阶段0需求与状态文档。

未来业务任务的输入格式、成果种类及保存期限待任务确定后补齐。

## 3. Agent 的主链路

上游设计为用户定目标、首席统筹、执行席制作、独立审核、修订与交回。本轮采用的离线工具负责配置与文件导出；真实模型与执行上下文由外部平台提供。用户尚未选择真实 AI 执行平台或首个任务，相关接入留到实际使用该能力时确定，不影响本轮离线运行和流程接入检查。

## 4. 什么算生成得好

本轮检查标准：本地入口可打开；至少一条现有代码路径真实执行并有结果；目录、管家、自检相互对应；失败和未测项如实记录。

未来 Agent 业务效果：待样例打分；不得把配置导出成功写成 AI 工作任务完成。

## 5. 交付阶段与优先级

导入、离线运行与阶段2-1已完成并确认。当前阶段3-0先出三版视觉稿；选定后阶段3-1做可交互代表页，阶段3-2统一工作台与既有工具外观并验收，最后本地收尾。用户本轮明确要求先视觉稿再跑Demo；没有云上线需求。

## 6. 模型与成本约束

本轮使用现成离线工具，不调用收费模型、不新增云资源。真实 AI 任务所需的模型厂商、平台和预算在选择平台及首个任务时确定，不借用其他产品密钥；这些未来输入不阻塞本轮检查。

## 7. 数据与非功能要求

本轮仅使用公开上游资料和合成测试数据，运行服务限本机回环地址。业务数据是否涉及隐私、允许使用的平台、留存规则待真实任务确定后补齐。

## 8. 上线与账号

本轮在本地使用现成离线工具，独立产品登录与云上线均不适用。若将来决定开发独立产品，再补齐账号、数据归属和上线要求，核实已有云环境及当时价格后按对应阶段推进。
