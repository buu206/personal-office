# 阶段3-1技术开发文档：深蓝机器人办公室Demo

日期：2026-11-18。用户已选择B并进一步指定围桌布局、蓝黑配色加暖黄灯光、机器人外形区分。以最新反馈为准直接实施代表页，不重复询问视觉或Demo授权。

## 1. 目标与范围

用户在左侧看项目与数据，在右侧输入任务，在中间看到不同机器人围桌协作及电视屏模拟进度；可选择角色、暂停和恢复演示、重载恢复项目。

本阶段新增主屏及相应持久化、构建、测试和浏览器证据。保留现有三页入口；全面修改旧页面样式留3-2。没有真实AI执行、云部署、外部发送、账号或费用。画面是分层2.5D，不支持自由转动镜头。

## 2. 实现与维护源

- `frontend/index.html`、`styles.css`、`app.mjs`：三栏布局、交互、蓝黄视觉与无障碍。
- `frontend/state.mjs`：版本化模拟状态和确定性流转；`frontend/tests/`：行为测试。
- `frontend/assets/conference.png` 是带中央长桌的会议室背景。`research-seat.png` 和 `design-seat.png` 提供持书与绘图的坐姿，另外三席沿用独立角色素材。`frontend/meeting.css` 控制两侧座位、桌边名牌和上身动作。
- `frontend/assets/team.json`：从当前上游团队提取ID/名称/职责，不带头像和凭证；默认五人演示团队，允许切换完整16席并每房间最多5人展示。
- `frontend/build.mjs`：从明确的源清单构建dist及三个旧工具，只发布需要的静态资源，不暴露data和证据目录。
- `scripts/start-demo.sh`：启动新Demo，回环地址；旧`启动.command`功能保持，新增`启动Demo.command`。
- `scripts/check-demo.sh`、`demo-roundtrip.mjs`：根验收阶段3-1调用的检查/恢复入口。

## 3. 状态与文件契约

状态schema为`personal-office.demo`，version=1，团队角色、项目列表、选中项目/角色、输入草稿一起保存。本机localStorage为持久化存储；导出JSON为备份，导入严格校验结构/大小/版本。恢复时running变paused，避免后台时间推进。

每个项目progress为0–100，research/write/design/review各占25%，左栏总进度与电视阶段进度从同一源计算；一次仅选中项目可以运行。状态包含初始、running、paused、completed、输入/保存错误；queued等仅为模拟子步骤，不表示实际后台队列。waiting_user为本地暂停/继续确认；streaming、真实API、真实权限、SSE和网络任务断连不适用。

保存失败不继续假装成功或推进；损坏存档保留原值并给恢复入口，不静默清空。新项目不覆盖旧项目，项目数量有上限；文件导入导出限JSON，不执行文件内容。UI使用textContent渲染用户输入，日志不记完整任务正文。

## 4. 用户流程与交互验收

1. 启动Demo，看到蓝黑房间与黄色灯光、不同轮廓机器人，以及常驻模拟标识。
2. 输入任务→开始演示→左侧项目、电视进度和角色状态同步变化；正在演示时防重复提交。
3. 点击机器人→看到对应名称、职责与演示环节；切换房间可看到全部团队成员。
4. 暂停/继续；重载后项目和输入仍在，运行项目暂停；导出后重新导入恢复。
5. 错误JSON、空输入、保存异常明确提示；原记录保持。重要控件能键盘操作，减少动画设置生效。
6. 390/768/1280/1440宽度截图；窄屏保留所有功能，不冒称手机真机验证。

## 6. 风险与回退

浏览器清理站点数据会移除localStorage，应导出备份；存储不可用时必须提示并暂停。2.5D素材只有五种视觉家族，完整16席靠编号/名称和分页区分，本阶段不声称16套独立模型。生成图不承担最终文字与进度，均由界面覆盖显示。

新代码、素材和构建与上游快照分开；回到旧入口即可使用原三个工具，用户文件不变。没有真实派工结果或平台权限影响。

## 工作流终端修订

在 `frontend/console.css` 维护代表页外层控制台。工作流、左侧仪表、节点输出和会议室后墙屏共用当前项目的模拟进度。点击节点可定位所属角色，点击角色可检查对应环节，跟随按钮恢复自动查看当前节点。输入框支持自然语言与组合键提交。完成后可单独导出当前项目及四个节点的模拟结果。


本次视觉修订为宝可梦草地工作营。背景为草坪、白云、树与围栏，皮卡丘统筹、妙蛙种子研究、杰尼龟撰写、梦幻创意、喷火龙审核。梦幻有独立悬浮动作。主屏主题维护于 frontend/pokemon.css，任务与存档仍由现有状态模块处理。新版以伙伴状态卡展示节点信息，素材来源见 docs/设计参考/宝可梦营地.md。


本次角色修订使用本地 Three.js 0.170.0 进行实时 WebGL 渲染。五种模型在 frontend/creatures.mjs 中由立体网格及关节组合构建，属于圆润简化造型。角色支持分段行走、转向、眨眼、四肢与尾部动作，飞行角色独立盘旋。草地上设定了错开的漫游区域，中央树桩区域留空。职位标签跟随投影，点模型或标签查看职责并触发短暂回应。原有静态角色仅作为 WebGL 不可用时的回退，界面会明确提示。减少动态效果设置会停用动作。Three.js 与许可证保存在 frontend/vendor，运行时无需请求 CDN。


最新代表页使用已确认的2D像素角色（frontend/pixel-camp.mjs），按实际速度选择八方向行走帧。人物卡以职位为主标题，包含角色立绘、属性、工作分工、当前任务进度与状态，点击卡片选中场景角色。属性对应所展示的宝可梦，任务进度来自现有模拟状态。16席团队按原有分页展示，本页每次最多五张卡。界面由 frontend/trainer.css 维护，使用红色委托图鉴、金边属性卡和训练师对话框。完整团队可能复用角色形象，职位及职责来自实际团队配置。

人员卡画像已改用场景同源的2D像素动作。按正面全部动画帧的非透明区域并集确定稳定边界，再等比缩放到留边的卡片画布中，避免动画中耳朵、翅膀或尾巴被截断。
