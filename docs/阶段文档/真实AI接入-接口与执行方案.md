# 真实AI接入：接口与执行方案（预研稿）

2026-11-18。待用户三个关键决定，不代表已实现。依据本项目源码、通用手册技术基线、上游岗位职责和官方模型接口。

## 已核事实与建议

当前`frontend/state.mjs`和`app.mjs`由tick模拟进度，项目只有id/title/progress/status；不包含真实产物、调用凭据或执行后端。上游README明确依赖宿主运行，导入的三个工具只编辑/导出文件。不能只替换一个模型名称就得到真实协作。

推荐增加Python3.12/FastAPI/Pydantic/pytest本机后端，沿用现有原生JS前端。Python3.12已存在，不必更换现有前端框架。任务、步骤、成果版本和预算账本存在SQLite，以事务约束预算预留和状态转换；单进程执行队列只处理本机任务，不引入云服务或外部调度平台。

## 运行与恢复

状态：queued→planning→writing→reviewing→revising（有限次数）→completed，另外有failed、cancelled、interrupted、needs_revision。只有通过结构校验、保存成果及审核结论后才记完成。审核只针对指定artifact版本及hash，首席不覆盖审核意见。

请求在途进程中断后记录interrupted，不自动重发未知结果的计费请求。恢复显示已完成阶段，用户确认重试才继续；预算预留保留到消耗核对，不靠重启清空。任务创建带幂等键，重复点击不创建重复付费工作。取消之后不再调度新步骤，已经发出的调用可能仍产生费用。

## API草案

统一前缀`/api/v1`；错误为`{"error":{"code":"...","message":"..."}}`，不回传底层堆栈。

| 接口 | 输入 | 输出与边界 |
| --- | --- | --- |
| GET /health | 无 | 服务状态，不带Key |
| GET /capabilities | 无 | 是否已配置、可用任务类型、模型标识、预算剩余，不回传敏感配置 |
| POST /tasks | 任务、标准、显式材料、团队快照、幂等键 | 已持久化任务id和状态；缺配置/超预算明确失败 |
| GET /tasks | 分页 | 当前用户任务元信息 |
| GET /tasks/{id} | id | 当前阶段、错误、已保存步骤和产物版本 |
| POST /tasks/{id}/cancel | id及版本 | 停止后续调度 |
| POST /tasks/{id}/retry | id、预期版本及幂等键 | 核验预算与状态后重试指定失败/中断步骤 |
| GET /tasks/{id}/artifacts/{version} | id和版本 | 本任务授权范围内的成果；服务端解析路径，拒绝遍历 |

第一版采用提交+轮询，无须为场景状态引入SSE。若用户确认需要流式文字，再实现chunk→done/error的闭合事件契约。浏览器轮询失败显示离线，不推进假进度。

## 模型与内容

模型调用放在单一provider层，接入用户确认的官方API；模型输出必须经过结构校验。模型请求的超时、空输出、非法JSON、限流及服务器错误用有上限的重试处理，每次可能计费的尝试均计入预算。Key缺失/初始化失败走统一错误，不启动假执行。

岗位职责来自用户选定团队并冻结为任务快照，保持首席/生产/审核职责分离。用户材料作为数据而非系统指令；模型无shell、任意文件读取、邮件、自动发布和充值权限。不能声称同模型分角色的审核能够保证内容完全正确。

## 与现有工作台兼容

新增真实任务存储和接口层；现有`personal-office.workspace.v1`演示存档保留，不原地修改schema或把旧模拟成果转换成真实记录。前端显示明确模式，进入真实模式必须API可用。卡片和场景不重设计，岗位工作状态从真实步骤映射，未启用岗位显示待命。

## 阶段验收影响

原`config/verification.json`只授权历史离线阶段。阶段2-2/3-3必须走真实模型检查，不加入offline白名单；当前verify对这个配置的未知阶段会拒绝，需要在实施时做显式AI验证配置/路由，将后端pytest、前端检查、真实冒烟、实际服务恢复纳入同一汇总，保留失败关闭与其他产品行为。

真实冒烟脚本在实际调用后记录时间、模型、请求id、token、耗时、校验及重试次数，不手写冒烟记录。mock测试只证明控制逻辑；真实效果仍须通过样例验收。没Key可完成已确认范围的本地代码与mock检查，阶段状态保留待验。
