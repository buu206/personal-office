## Host behavior to check

**Check OpenMaus settings at all three levels.** Both native imports showed Full Access despite `ask` in the file. Earlier per-role changes to Ask and readbacks establish only the settings of the original chats opened at that time; they do not establish the Bot default or Ask in every later child chat.

Static inspection of this version shows that a new direct delegated child chat starts from the receiving Bot's role default, not Ask in that Bot's original chat. In the lead-dispatch path examined here, the lead's Ask is not an approval ceiling for the recipient; native lead delegation can also raise the receiving chat's level. Ask in the chat bar changes only the current chat. In the observed Profile → Permissions → Approval level panel, Ask changes the Bot default without automatically overriding existing chats explicitly set to Full; this does not describe every control with the same label. Ask does not guarantee a completely read-only session, a prompt before every step or zero background writes.

At the initial discovery, the Inspection Bot default was Full Access. Subsequently, within the limited test scope, the operator individually changed the defaults of all 16 Bots in this department from Full to Ask and read them back in the native UI. One subsequent new inspection child chat also displayed Ask without the operator changing that new chat's permission setting. This establishes the actual setting for that delegation, not Ask in every old or future chat. The 16 visible existing direct chats have also been individually read back as Ask, but historical work chats have not all been checked. The later round completed only a limited synthetic text review. The earlier separate change to the already-stopped chat remains recorded as operator intervention; it does not turn the original run into a completed business task.

**Text return and attachment return are separate capabilities.** In the group trial, source quantities 3, 5 and 2 summed to 10; the deliberately incorrect draft claimed 11. The assistant and reviewer independently found the discrepancy, and the lead returned the rejection without editing the originals. The host refused the lead's attempt to attach records outside that chat's working directory and not saved in that run. Files remained available in their designated directories; end-to-end attachment return did not pass in that case.

In the later limited implementation task, the executor attached two target texts in the Engineering group. The root downloaded them through the native interface and confirmed that attachments, targets and sources were byte-identical. The lead's original chat returned a text conclusion and four local file entries, without native file-attachment cards. Clicking the first Save a copy entry was refused by that chat's working-directory boundary; the other three were not tested further. The two group downloads passed, but file download in the lead's original chat did not work. This does not establish automatic attachment relay to the lead. Local file links and native attachments use different read paths; a rendered link button does not guarantee download access.

**One group-rule check explicitly failed.** The limited task's formal group dispatch disclosed an internal absolute path, contrary to the Engineering group's current rules. Omitting paths from the execution and review replies did not undo that upstream breach. Successful placement, review by someone other than the executor, and the lead's text receipt do not establish full group-rule compliance.

**Rules, authority and actual channels must align.** The trial used a one-task registration for synthetic data, without changing standing rules. Its prompt was entered by the test operator; it does not establish independent verification of the human's identity, original authorization wording or private-data retention policy. Receiving roles must actually read the relevant full-rule sections.

These are local team observations and artifact checks, without complete provider-side logs. Displayed tokens, cache rates and estimated costs were not reconciled to billing and do not support a cost-saving claim. Independent first-time setup success and long-term reliability were not measured. The listed project-authored materials now use MIT, including commercial use; see [NOTICE](../NOTICE) for scope and exclusions. This is a release candidate. License adoption does not expand the verification claims above.
