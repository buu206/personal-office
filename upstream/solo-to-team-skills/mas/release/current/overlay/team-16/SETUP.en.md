# Bring the 16-role team to your host

[Back to the builder](index.html#en) · [中文](SETUP.zh.md) · [This round: observed results and limitations](VERIFICATION.en.md)

The template contains **16 roles, six groups and 26 suggested memberships**. A first task may use only the lead, producer and reviewer; activate other roles as needed. The complete template remains editable and exportable.

Check duties, memberships and handoffs, then select **Save team file**. Keep this JSON for future edits. Duties and group descriptions retain their indentation and line breaks. After removing roles, check the current duties and group descriptions listed in the reminder. Membership lists update automatically; you review and edit the prose. The reminder only flags unselected role names mentioned in text; it does not reassign duties or determine authorization. Choose a host below and download its file. A download does not create accounts, roles, tasks or tool permissions.

## OpenMausBot

1. Select OpenMausBot. Select each native room you need; rooms are off by default and selected rooms default to mentions only.
2. Download the department JSON. In the host's new/share entry, open Templates and Import, then select the file. Review the actual roles and rooms and resolve name conflicts before adding it.
3. **Check the Bot default, the current chat and each new delegated child chat separately.** Full Access still appeared after native import in 0.1.148; `ask` in the file is not proof of actual permissions. In the role's Profile → Permissions → Approval level, check the default, then read back the actual chat settings. Changing to Ask in this profile panel does not automatically narrow existing chats explicitly set to Full; Ask in the chat bar changes only that chat. New delegated work starts from the receiving Bot's default, so Ask in the lead's original chat is not a substitute for checking. If a setting conflicts with this task's requirements, stop that run and resolve it.
4. Download the full group rules from the builder. Provide applicable sections to each assistant and ask it to read back its duties, commissioning source and return recipient. The JSON includes summaries; full references are not loaded automatically and must not override your edited configuration.
5. Before the first task, check the allowed directories, inputs and return channel. A local link or Save a copy button is not proof that a file can be downloaded; open it and check. In the Engineering group, use only agreed file codes or relative names, and provide sensitive location details through an approved channel. Verify actual execution, independent review and return before relying on the workflow.

## DeepSeek Harness

1. Select DeepSeek Harness, keep Native project and download the ZIP.
2. Extract it into a new empty directory. Select the level containing `team.definition.json` as the workspace and retain the hidden `.dsh` directory.
3. Start a fresh chat, use `/solo-to-team`, and ask for a roster and task-assignment check. Groups describe collaboration; they do not create native rooms.
4. Full rules are under `references/template-rules/`. Have the responsible role read relevant sections. The root session dispatches and returns work; production and independent review use different roles. Files alone do not prove delegation.
5. Run a small, checkable task and inspect actual subtasks, artifacts and review records before using formal materials.

The optional DS Bot plan is a separate integration. It is based on the stated source version and has not passed live DS Bot team-creation acceptance. Follow that entry's own instructions.

## WorkBuddy

1. Attach the ZIP in My experts → Create expert team and request a **private import**. Check names against existing experts first.
2. Inspect what was actually created. The template has 16 roles; historical testing of a three-role starter neither establishes a platform-wide three-role limit nor guarantees that your account can create or run all roles together.
3. A first task can use the lead, producer and reviewer. Lead-only transport does not replace specialist commissioning relationships: relays must retain the original commissioner, authority and return recipient.
4. Full rules are under the team's `references/template-rules/`, also named in each role card. Request a readback of relevant sections; an included file is not proof of receipt.
5. Verify an appropriate channel before private consultations or direct-to-user reports. If the host lacks it, disclose the capability gap without routing protected results through the lead.

## Grok Bot

A new Bot may greet the user directly on first startup. After creation, inspect actual message routing and use a non-sensitive sample to check acceptance and return recipients. In one trial, the executor reported, based on platform conversation records, that shared user context was automatically supplied to that Bot; a custom role description does not establish isolation. Checking the submitted description’s hash is not a full readback of the saved profile. If the task requires strict isolation, before creating or first starting the Bot for that task, verify that the host supports it and that the required isolation is already in effect; withhold material requiring isolation until this is established. Check whether shared context is injected and its scope without requesting or forwarding its contents.

1. Select Grok Bot, enter a batch ID and download the guide ZIP. Reuse the ID when resuming the same batch.
2. Open `Start-here.html`, attach `grok-plan.json` to your main Bot chat, and copy the preview request. Reconcile existing roles, missing roles and bindings before acting.

## What a successful first task shows

The actual executor receives the correct input version and returns an openable artifact. A different reviewer opens that same artifact. Corrections go to the actual executor, and the original chat receives the revised artifact with the review outcome. Role counts, successful exports and a Done label each establish only their respective step.
